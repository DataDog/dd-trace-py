# Add Lint Rule

New lint or static-analysis checks follow this order. Do not skip a level
without a concrete reason written in the PR.

1. **ast-grep** if the pattern is expressible as AST / text / comment matching
2. **Existing static analysis tools** otherwise (Ruff, Bandit, mypy, codespell,
   CodeQL, Datadog SAST)
3. **Hand-rolled scripts as a last resort**

A check that is not wired into CI does not exist. Unit tests for the checker
are not a substitute for a blocking job.

`@DataDog/python-guild` owns lint config. See CODEOWNERS.

## 1. ast-grep (first choice)

Use this for structural or textual patterns in source: forbidden calls,
import style, comment/docstring markup, naming, AST shape.

| Path | Role |
| --- | --- |
| `sgconfig.yml` | Rule and test dirs |
| `.sg/rules/<id>.yml` | The rule |
| `.sg/tests/<id>-test.yml` | Valid / invalid fixtures; `id` must match |
| `.sg/tests/__snapshots__/<id>-snapshot.yml` | Generated by `scripts/lint sg-test` |

Copy an existing pair such as `.sg/rules/no-rst-double-backticks.yml`.
CI already runs `scripts/lint sg` and `scripts/lint sg-test` in **`ast-grep rules`**.
A new `.sg` rule needs no new GitLab job.

```bash
scripts/lint sg-test
scripts/lint sg -- <path>
```

ast-grep cannot do git-diff incremental enforcement, Sphinx `automodule`
lookup, or import-graph / whole-repo analysis. Those may justify a later
level.

## 2. Existing static analysis tools

Turn on or configure a rule the repo already runs. Do not add a new tool
or script if Ruff (or similar) already has the check.

| Tool | Config | Already runs in |
| --- | --- | --- |
| Ruff | `pyproject.toml` `[tool.ruff]` `lint.select` / `lint.ignore` | `prechecks` Style |
| Bandit | `pyproject.toml` `[tool.bandit]` | `prechecks` Security |
| mypy | `mypy.ini` | `prechecks` Typing |
| codespell | `setup.cfg` `[codespell]`, `.codespellignorelines`, `docs/spelling_wordlist.txt` | `prechecks` Spelling |
| cython-lint | `pyproject.toml` `[tool.cython-lint]` | `prechecks` Style |
| clang-format | `.clang-format` | `prechecks` Style |
| cmake-format | `scripts/.cmake-format` | `prechecks` Style |
| CodeQL | `scripts/codeql_scan.sh` | `codeql-scan` |
| Datadog SAST | `static-analysis.datadog.yml` | platform scan |

Tool versions: `pyproject.toml` `[dependency-groups] lint`.

```bash
scripts/lint style -- <path>    # Ruff / format
scripts/lint checks             # full local gate
```

## 3. Hand-rolled scripts (last resort)

Allowed only when levels 1 and 2 cannot express the rule. Typical cases:

- Incremental "new on this PR" via `git merge-base` (ast-grep scans the
  current tree, not the diff)
- Docs graph / `automodule` membership
- Import-graph or layering analysis

If you add `scripts/check_*.py`:

1. State in the PR why ast-grep and the existing tools cannot do it.
2. Wire a **blocking CI job**. Tests that import the script are not enough.
   - Full-tree, path-filtered check: add a section in
     `scripts/gen_gitlab_config.py` `gen_pre_checks()` and a
     `scripts/lint` subcommand included in `checks`.
   - Diff-vs-base incremental check: add a parent-pipeline job in
     `.gitlab-ci.yml` modeled on `check_type_comments` /
     `check_no_new_aidev_anchors` (`GIT_DEPTH: "0"`, resolve base branch,
     `python3 scripts/check_….py --base-ref FETCH_HEAD`).
3. Add `scripts/lint <subcommand>` so the check can run locally.
4. Prefer extending an existing checker over a new file.

```bash
scripts/lint <subcommand>
```

## Decision examples

| Need | Implement as |
| --- | --- |
| Forbid `span.set_tag("manual.keep")` | ast-grep |
| Enable a Ruff rule (`UP006`, etc.) | `lint.select` in `pyproject.toml` |
| Ban rST ``literals`` in comments | ast-grep (see `no-rst-double-backticks`) |
| Ban rST only in *non-rendered* docstrings, new lines only | script (needs automodule set + diff) |
| New circular-import or layering invariant | extend `scripts/import-analysis/` |
